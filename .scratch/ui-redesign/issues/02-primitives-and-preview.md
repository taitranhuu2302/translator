# 02: Primitives and the preview harness

**What to build:** The shadcn components this app actually uses, plus a dev-only harness that renders them and every surface state with mock data — so the design is reviewed in a browser instead of a build cycle. The harness is born here and grows with tickets 03–07.

**Blocked by:** 01

**Status:** resolved

- [x] Each installed component renders with Neris tokens; no component is left on shadcn's default palette.
- [x] `Button` covers the states the app needs: primary, secondary, outline, ghost, destructive, plus busy and disabled.
- [x] `ui/preview.html` + `ui/src/preview/` render all five surfaces with mock data.

- [x] The harness uses the same components the app will, not look-alike markup.

## Implementation

- All sixteen components live in `ui/src/components/ui/`, generated by
  `npx shadcn@latest add <name> -c ui` and then edited in place. They resolve
  `cn` from the `cn` package and every colour through the `@theme` tokens, so
  there is no component-level palette to drift.
- `Button` has `default` (primary), `outline`, `secondary`, `ghost`,
  `destructive` and `link`, with `xs`/`sm`/`default`/`lg`/`icon-xs`/`icon-sm`/
  `icon`/`icon-lg`. Busy is a `LoaderIcon` inside the button rather than a
  variant — the ticket asked for the state, and a spinner child is how both the
  panes and the sheets draw it; disabled is the primitive's own
  `disabled:opacity-50`.
- `ui/preview.html` + `ui/src/preview/` are the harness. `PreviewApp.tsx` owns
  the scene list and a `PreviewBar` picker; `mockIpc.ts` holds the one mock
  settings object; `PopupPreview.tsx` is the separate popup entry. Scenes are
  addressed by URL hash (`#translate-long`, `#onboarding`, …) so any state can be
  linked and reloaded.
- The preview draws the real surfaces — `AppShell`, `TranslatePanes`,
  `HistorySheet`, `SettingsSheet`, `NoticeView`, `Onboarding`, `Popup` — and only
  the IPC seam is faked. Nothing in `ui/src/preview/` is imported by the app.
- The harness carries, by ticket: the five window surfaces (this ticket), the
  two modes and their states (04), History and Settings including both failure
  states (05), the popup's four states (06), and every notice kind plus the
  resolved Accessibility card drawn through `CaptureNoticeView` (07).
- `ui/vite.config.ts` lists only `main` and `popup` in `rollupOptions.input`.
  The harness HTML entries are reachable from the dev server by URL and cannot
  enter a production build, because Rollup only follows declared inputs; the
  scenes' mock data is imported exclusively from `preview/`, so it is not in the
  graph either.

## Comments

- 2026-11-16 — `Button`'s busy state is a spinner child, not a `busy` prop. A
  prop would have had to be threaded through every call site that already has
  its own "is it running" flag; the child keeps the decision where the flag is.
